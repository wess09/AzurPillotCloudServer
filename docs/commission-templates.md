# 委托事件与未知物品模板升级

## 审计后的兼容与一致性

升级还会执行 `0005_review_consistency.sql`，不修改已发布的 `0004`。同一像素和标签下的不同候选 ID 分别保存，旧版本已合并的关联从原始结果中恢复；完全匹配的 `missing_template` 也可以在映射补齐后解决。名称、数量和配对错误仍然阻止整组统计。

跨结果重复的稳定 `record_id` 会正常确认并保留原始报告，有效事件视图只计一次，正式结果优先，来源排序固定。物品统计通过事件来源和序号关联该视图。未知图标的正式匹配缓存绑定资源版本；改名、禁用或规则变化后重新匹配并订正受影响来源，相同识别内容的重复发布保留有效缓存。升级后发布一次新资源，使旧回执缓存进入当前版本。

拆出最后一个图标后，源簇不再保留已移动的代表图，空簇仅保留历史身份，不参与匹配或管理台目标选择。有剩余图标时从实际归属中补选代表图；回滚同时恢复哈希归属和可用的代表图。

历史资源先核对摘要，已签名版本使用该版本保存的公钥验证；启用签名前的完整未签名版本仍可读取。对外返回的内容使用当前部署密钥签名，因此启用签名或轮换密钥后仍可读取历史版本和生成增量；B 的固定公钥仍需由管理员同步。损坏摘要、缺失一半的签名字段或无效历史签名均拒绝读取，回滚也执行相同检查。

`RECOGNIZER_URL` 在非回环地址默认要求 HTTPS，匹配和预览请求都禁止携带令牌跟随重定向。隔离的私有网络确需 HTTP 时，管理员显式配置 `ALLOW_INSECURE_RECOGNIZER=true`；`localhost`、IPv4／IPv6 回环 HTTP 无需此开关。

数据库迁移在创建版本日志前取得数据库级事务锁，避免并行启动重复建表／加列。统计查询先物化当前筛选下的收益行，再关联样本分母，避免复杂复核视图反复展开及三表嵌套扫描。服务连接默认关闭 PostgreSQL JIT，管理员可通过连接串的 `jit=on` 显式覆盖。

设备 ID 继续作为客户端来源字段和临时分发观察数，不作为独立身份认证。按现有计划保留五个不同设备 ID 的分发门槛，不额外加入人工批准；委托配对始终以上传组边界及图片顺序为准。

本仓库是三节点统计流水线的 C，B 对应 `AzurPilotStatsWorker`。本次保留既有上传、批次、结果修订和查询入口，增加委托维度、全局未知身份和签名资源。客户端本地采集及 A 的上传协议不在此变更范围。

## 接收委托事件

`POST /internal/v1/statistics/results` 继续接受既有结果信封；`parser_version=azurpilot-adapter-v4` 的委托事件必须有 `record_id/name/status`，并可携带英文 `comm`。`project` 保持中文名称，`status=0/1` 分别表示成功／大成功。时长由 B 的固定委托目录提供，活动委托代码为空时不计算时均。

零奖励的 `PlaceHolder:1` 计入样本分母，但不会出现在物品明细。新委托收益按名称、`comm`、成功状态分别计算，样本数严格大于 50 才显示收益行。旧结果缺少新增维度时仍按旧口径展示；不能从旧数据倒推出成功状态，需要 B 重新识别才能补齐。

公开 `/api/v2/get/drop`、`/time-slots` 在原有维度之外返回 `comm/status`，支持 `comm=<英文代码>&status=0|1` 筛选；省略则分组返回两种状态。公开页面在收益明细显示委托名称、夜间标记及成功状态。所有时段继续使用源 `collected_at`。

迁移 `0004_commission_icons.sql` 增加委托列、稳定记录标识、复核事件／物品、未知图标／簇／映射、别名与哈希覆盖表，以及资源签名字段。原有正式记录保持有效，待复核事件另存于 `stat_review_events/items`。`stat_effective_*` 视图只在整组诊断全部属于未知模板、所有候选均有关联行、且每行都可解析时恢复统计。任何名称、数量、配对或图像错误都会继续阻止整组统计。原始结果和修订历史不因发布映射而改写。

## 全局未知身份

配置 `RECOGNIZER_URL/WORKER_TOKEN` 后，C 使用 B 的认证匹配接口。候选 PNG 字节摘要保持候选 ID，C 解码校验后重新计算 49×49 RGB 像素摘要作为全局 `local_key`；96×96 整格按 `(40,21)-(89,70)` 裁剪。不同场景、设备或 PNG 编码下的相同像素只对应一个身份。

L0 查全局像素摘要；未命中时，C 读取一致的正式／未知模板快照，再调用 B 做 pHash／颜色筛选与 OpenCV NCC。默认正式 ≥0.92、未知簇 ≥0.96、不同规范身份间隔 ≥0.03；0.85 以上可附疑似物品供人工确认。正式名命中不新建 U；否则复用或新建 `U-xxx`。每簇固定代表图和最多八张额外 exemplar。新哈希与簇在同一事务内创建，快照变化时重新匹配，解码和网络匹配不占用数据库的聚类锁。事件接收不使用聚类锁。

内部候选回执新增 `match/item?|key?/local_key/revision/need_screenshot`。B 可缓存已确认图标；相似但尚未确认的新像素仍须经过 C。回执后，B 在结果被接收时向 `/internal/v1/unknown-screenshots` 登记来源引用，每簇最多三个有效引用，90 天过期，分类／忽略后删除引用。123 盘已经保存长期原图，C 通过原有认证预览按需读取；不会二次存储或删除 123 盘原图。

管理台可查看委托上下文和相似物品提示，人工确认分类；“修正未知物品归属”支持合并整簇或仅拆出当前图标。

| 操作 | 管理 API |
|---|---|
| 查看最近未知簇 | `GET /api/v1/admin/unknown-clusters` |
| 合并 | `POST /api/v1/admin/unknown-clusters/merge`，`{from_key,to_key}` |
| 拆分一个像素身份 | `POST /api/v1/admin/unknown-clusters/split`，`{from_key,to_key?,local_key}`；目标为空则新建 U |
| 分类／忽略 | 原有 `PATCH /api/v1/admin/template-candidates/{id}` |

合并使用别名，拆分使用像素哈希覆盖，均发布为新资源版本；冲突的人工物品名称需先修正后再合并。正式物品标识剥离末尾 `_数字` 变体，禁止使用 U 命名空间。禁用模板会撤下对应映射，回滚可以恢复映射和历史统计。

## 签名资源与增量

配置 C 的 `TEMPLATE_SIGNING_KEY`（Base64 Ed25519 32 字节种子或一致的 64 字节私钥），把对应原始 32 字节公钥以 Base64 写入 B 的 `TEMPLATE_PUBLIC_KEY`。密钥通过部署环境提供，禁止提交到 Git；B 不从响应头动态信任公钥。

资源包含 `schema_version=1/revision/templates/mappings/aliases/hash_overrides/match_thresholds`。模板保存 PNG 摘要 `sha256` 和规范像素摘要 `icon_sha256`，发布时统一为不透明 49×49 RGB。至少五个不同设备观察到的待分类簇才分发为临时模板；正式模板优先，临时默认阈值 0.95。原生整格匹配继续保留 OpenCV NCC。

- 新 B 对 `/internal/v1/template-releases/{id}` 发送 `Accept: application/vnd.azurpilot.template-bundle+json;version=1` 获取完整快照；旧 B 不发送该能力标识，只收到正式模板数组。
- `/api/v3/get/templates/manifest` 返回活动版本、摘要、场景、到期时间并支持 ETag。签名位于响应头。
- `/api/v3/get/templates/delta?from=<revision>` 返回增量和删除墓碑，`from=0` 返回完整包。`/api/v3/get/mappings` 复用相同参数和签名快照，包含映射及别名的增量。
- 增量包含 `base_revision`、模板 `deleted`，以及 `deleted_mappings/deleted_aliases/deleted_hash_overrides`。规则、映射、别名和阈值均绑定同一修订版。
- `X-Content-SHA256` 校验响应原始字节；`X-Content-Signature` 为下列消息的 Ed25519 签名，再编码为 Base64：`azurpilot-templates-v1\n<revision>\n<SHA256原始字节的小写十六进制>`。

发布在单事务中保存不可变内容、签名和映射、切换活动指针并登记必要的重识别任务。只有显示名称变化时不重复 OCR；模板内容、身份或匹配规则变化时会订正受影响记录。回滚复制旧资源为更大的新版本，同时恢复映射、别名、拆分覆盖及阈值；模板编辑草稿仍保留当前值。B 验签、逐文件校验并原子应用快照，失败继续使用旧版。

## 部署与验证

先备份并升级 C，服务启动执行 `0004` 迁移，再配置 C 到 B 的匹配／预览地址及成对密钥，发布一次新资源，最后升级 B。旧记录无需立即重跑；需要新增维度的历史委托由管理员触发重新识别。密钥为空保留旧协议兼容，公开 v3 资源接口会返回未配置签名；启用固定公钥的 B 拒绝未签名包。轮换密钥后重新发布活动内容并同步 B 的固定公钥。

本地验收使用独立 PostgreSQL、B 的固定 OCR 模型和真实截图副本。45 组、62 张原图经实际 B → C HTTP 接收，37 组完成、8 组复核；14 组委托中 4 组有收获页并核对名称／物品／数量，10 组按默认设计产生 PlaceHolder。另验证未知身份并发、分类后历史解析、其他错误仍阻断整组、签名增量、禁用／回滚、合并／拆分和样本分母。原图和本地验证产物不提交。该抽样不代表全部用户截图的总体准确率，也不涉及真实云盘、Tunnel 或生产数据库写入。
